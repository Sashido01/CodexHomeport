# Сопровождение и релизы

[English](../en/MAINTENANCE.md) | [Политика CI](CI_POLICY.md)

Используйте штатные Git и GitHub CLI. Перед коммитом проверьте учётную запись и авторство в локальном репозитории:

```powershell
gh auth status
gh api user --jq '.login'
git config --local --get user.name
git config --local --get user.email
git remote -v
git status --short --branch
```

Исходный репозиторий публикует только авторизованный сопровождающий. Владельцы форков используют свои учётные записи. Установите локально `git config --local user.name "ВАШ_ЛОГИН"` и `git config --local user.email "ВАША_ПОДТВЕРЖДЁННАЯ_ИЛИ_NOREPLY_ПОЧТА"`. Почта должна быть привязана к аккаунту GitHub либо соответствовать формату `ID+LOGIN@users.noreply.github.com`. Не используйте фиктивные адреса. До отправки проверьте `git log -1 --format=fuller`.

Уже опубликованные коммиты сохраняют автора, пока история не переписана. Ради скрытия подписи не переписывайте опубликованные релизы.

Делайте небольшие понятные коммиты. Синхронно обновляйте документацию на двух языках, `CHANGELOG.md`, `VERSION`, движки и меню при увеличении микроверсии. Тег создавайте только после проверок. Разделяйте PASS, FAIL, NOT_VERIFIED. Локальные JSONL и личные снимки храните вне Git. Не делайте force-push и не переносите теги. Завершив приёмку, прекращайте задачу.
